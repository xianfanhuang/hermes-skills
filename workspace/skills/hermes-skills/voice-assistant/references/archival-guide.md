# 语音消息归档特性指南

## 上下文影响

| 方面 | 说明 |
|------|------|
| **存储方式** | 语音转录后以文字形式存入上下文 |
| **Token消耗** | 与同等长度的文字输入相同 |
| **额外开销** | 无额外音频文件存储开销 |
| **建议** | 长语音（1分钟+）建议分段发送 |

## Session归档

| 特性 | 说明 |
|------|------|
| **归档内容** | 转录文字（不包含音频源文件） |
| **归档格式** | Markdown格式，可搜索 |
| **存储位置** | memory/sessions/ 目录 |
| **音频文件** | 存储在 media/inbound/ 目录 |

## 搜索能力

| 类型 | 可搜索性 | 说明 |
|------|----------|------|
| 转录文字 | ✅ 可搜索 | 通过memory_search工具搜索 |
| 音频文件 | ❌ 不可搜索 | 音频文件不进入搜索索引 |
| Session归档 | ✅ 可搜索 | Markdown格式，支持全文搜索 |

## 存储管理

### 音频文件存储
- **位置**: `/workspace/projects/media/inbound/`
- **格式**: OGG OPUS
- **保留时间**: 可能被系统清理
- **建议**: 重要内容及时转录保存

### 转录文字存储
- **位置**: Session transcript (JSONL格式)
- **保留时间**: 长期保留
- **备份**: 通过sync-to-backup脚本同步

## 最佳实践

1. **短语音**（30秒内）：直接使用，无需特殊处理
2. **长语音**（1分钟+）：建议分段发送，避免上下文膨胀
3. **重要内容**：及时转录保存，不要依赖音频文件
4. **搜索需求**：使用转录文字搜索，不要搜索音频文件

## 团队协作建议

1. 建立统一的语音使用规范
2. 重要内容及时转录归档
3. 定期清理过期音频文件
4. 使用memory_search工具搜索历史内容
